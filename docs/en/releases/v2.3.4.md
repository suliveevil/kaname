# Kaname 2.3.4

[English](v2.3.4.md) · [中文](../../zh-CN/releases/v2.3.4.md)

A reliability release covering the nine days since 2.3.3: the floating panel now appears over
another app's native full-screen Space, paging no longer changes the window's height, shortcut
replay and surface ownership were hardened, and the release build works again on macOS 27.3
where Xcode's macro sandbox cannot start.

## Highlights

- **The panel opens on the Space you are looking at, including another app's full-screen
  Space.** A native full-screen Space belongs to the owning app's window set; `.canJoinAllSpaces`
  only grants membership of every desktop, so the one reused panel stayed on the desktop where
  it was last shown when WorkBuddy or Safari was full screen. The window now also declares
  `.canJoinAllApplications` (macOS 13+) and drops `.stationary`, AppKit's desktop-like behaviour
  that held it on its birth Space. The `.statusBar` level and the accessory app policy are
  unchanged. A field test on 2026-11-16 recorded 19 panel sessions and 222 redraws across
  WorkBuddy and Safari in native full-screen Spaces with zero off-Space readings; the same
  sequence read `onActiveSpace=false` three times on the 2.3.3 build.
- **The off-Space re-anchoring and the one-shot self-heal are retained and labelled
  unverified.** The corrected membership declaration resolved every reading in that test, so
  neither fallback branch ran. They stay as a defensive path for a future WindowServer change,
  with the test result recorded in the source comments and in the changelog.
- **Paging to a page with one more section card no longer changes the panel's height.** Rows
  and headings were already sized from the session's widest list; the cards' insets, the
  hairline under a card's title and the gaps between cards were still counted from the groups
  on the current page. A first page holding only the app's card was 20 pt shorter than the
  next one, which also carried the system hotkeys — visible as `1368x702` / `1368x720`
  alternating in the log. `PanelState.cardBudget` now carries the third count from
  `PanelSections.cardAndHeadingBudget()` through `EngineState.rowBudgetCache` into
  `OverlayMetrics`, and the title hairline follows the session's heading budget. Three new
  size-stability tests bring the suite to 936.
- **Shortcut replay and surface ownership.** Search replays record usage only after a chord is
  posted; app launch and termination notifications refresh the app list used by search scopes
  and conflict scans; system-hotkey reloads and config-file scans rebuild an open panel or
  search palette instead of leaving the previous results visible. Overlapping swallowed key
  presses are tracked independently, so one key's release cannot expose another key's repeat
  to the app behind a dismissed surface. Panel and search runs capture their target app before
  asynchronous Accessibility resolution, and chord replay preflights every step — including
  alternate key spellings — before activating the target or posting an event. Replay
  completions, search activation hand-offs and cursor restoration are owned by their surface
  session; replacing a surface or stopping the engine invalidates old work instead of letting
  it inject into a later app.
- **Focus-change dismissals now say why they happened.** A frontmost change that closes a panel
  logs the panel's age, the Space switch's age and both pids. The 2026-11-16 timeline showed
  the Finder activation 1.3 s after the panel opened was a real app switch, so the dismissal
  contract stays as it was: leaving the app closes the panel. A trigger inside a Space-switch
  animation still shows the panel at once — holding it back would swallow keys with nothing on
  screen — and gets one re-layout when the 0.75 s settle window ends.
- **Release and backup automation.** Release CI propagates a failed Release build through its
  log pipeline; the publisher refuses an existing tag that does not point at the commit being
  published, and a matching-tag retry generates notes from the previous release. Local-signed
  DMGs no longer require timestamp-network access, and backup dry runs no longer predict a
  deletion while the retention limit still has room. The 2.3.3 source build number was set to
  233, distinct from 2.3.2's 232, and SwiftPM test hosts use explicit `nonisolated` isolation
  so the suite stays compatible with the Swift 6.1 CI toolchain.
- **Building on macOS 27.3.** `sandbox-exec` returns `sandbox_apply: Operation not permitted`
  on this system, so Swift's macro plugin server cannot start and `@Observable` expansion used
  to fail with "produced malformed response" — the macro libraries themselves are intact.
  `build_release.sh` now detects that condition and passes `-disable-sandbox` to `xcodebuild`;
  if the Xcode build still fails, it falls back to `scripts/build_swiftc.sh Release`, the same
  fallback `install.sh` already used. The DMG for this release was built through the Xcode path
  as a universal binary.
- **Repository assets.** Product renders, a data-flow diagram, an interaction diagram and a
  swimlane SVG live under `assets/`. On 2026-11-18 the three diagrams were re-checked against
  `ba3cd43` — they now record the full-screen Space membership fix, the session-wide card
  budget and the focus-change attribution log — and the eight screenshots in `docs/images/`
  were re-captured from the installed 2.3.4 build.

## Upgrade notes

- Settings, per-app statistics, logs and local backups carry over unchanged. The bundle
  identifier and the signing identity are unchanged, so an Accessibility grant survives the
  update.
- The panel still closes when you leave the app or switch Space; summon it again for the new
  front app.
- Full-screen coverage was measured on WorkBuddy and Safari on one display. Multiple displays
  and apps that use `CGShieldingWindowLevel` sit outside that test.
- The off-Space re-anchoring and self-heal branches have no runtime evidence behind them; the
  verified fix is the collection-behaviour declaration.

## Install

```
brew tap suliveevil/tap
brew install --cask kaname
```

Already installed:

```
brew upgrade --cask kaname
```

The tap's cask was updated to 2.3.4 on 2026-11-18 (`suliveevil/homebrew-tap@1eddadd`), so a fresh `brew install` now resolves to this build.

The build is signed but not notarized, so macOS blocks the first launch with an
"unverified developer" notice: open **System Settings → Privacy & Security**, click
**Open Anyway**, or run `xattr -dr com.apple.quarantine /Applications/Kaname.app`.
Grant **Accessibility** when asked; add **Input Monitoring** only if the panel does not
appear.
